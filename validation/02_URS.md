# 用户需求规格 (User Requirements Specification)

**文档编号：** VAL-URS-001  
**版本：** 2.0  
**生效日期：** 2026-07-24  

---

## 1. 目的

本文档定义了 君合盟药物警戒君合盟药物警戒培训管理系统 (PV Training Management System) 的用户需求，涵盖功能需求、非功能需求、数据完整性需求和合规需求。所有需求均可追溯、可测试。

## 2. 需求编号规则

需求编号格式：`URS-[模块]-[序号]`

| 模块代码 | 模块名称 |
|----------|----------|
| USR | 用户与账号管理 |
| CRS | 课程与资料管理 |
| EXM | 考试管理 |
| PLN | 培训计划 |
| LOG | 日志与审计 |
| CFG | 系统配置 |
| SIG | 电子签名 |
| SEC | 安全与权限 |
| INF | 基础设施 |
| QBN | 题库管理 |
| ATP | 自动出卷 |
| PPT | PPT 自动生成 |
| AI | 大模型接入 |

## 3. 功能需求

### 3.1 用户与账号管理 (USR)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| USR-001 | 系统应支持创建、编辑、删除用户账号 | 高 | 21 CFR 11 |
| USR-002 | 每个用户应有唯一的用户名/工号 | 高 | 数据完整性 |
| USR-003 | 用户密码应满足复杂度要求（最少8位，含字母+数字） | 高 | 信息安全 |
| USR-004 | 系统应支持通过 Excel 批量导入用户（最多300个） | 中 | 效率 |
| USR-005 | 用户应归属于一个部门，并可分配角色（管理员/培训管理员/学员） | 高 | RBAC |
| USR-006 | 系统应记录用户的登录/登出时间戳 | 高 | 审计追踪 |
| USR-007 | 用户应可查看和编辑个人资料 | 低 | 用户体验 |

### 3.2 课程与资料管理 (CRS)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| CRS-001 | 系统应支持多级课程分类管理 | 中 | 组织结构 |
| CRS-002 | 系统应支持上传 PPT、Word、PDF、视频等培训资料 | 高 | 功能完整性 |
| CRS-003 | 课程应包含审核工作流（草稿→待审核→已批准→已发布） | 高 | 变更控制 |
| CRS-004 | 系统应记录课程创建者、审核者、发布时间 | 高 | 审计追踪 |
| CRS-005 | 视频资料应支持进度跟踪（防作弊：单次跳跃不超过30秒） | 高 | 数据完整性 |
| CRS-006 | 系统应自动计算文件大小并显示 | 低 | 用户体验 |
| CRS-007 | 系统应支持根据课程资料自动生成 PPT 课件（python-pptx） | 中 | 效率 |
| CRS-008 | 课程资料应以彩色图标区分文件类型（PPT/Word/PDF/视频），视频和 PDF 支持内嵌预览 | 中 | 用户体验 |

### 3.3 考试管理 (EXM)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| EXM-001 | 系统应支持5种题型：单选/多选/判断/填空/简答 | 高 | 功能完整性 |
| EXM-002 | 考试应设置时长限制，超时自动提交 | 高 | 公平性 |
| EXM-003 | 单选/多选/判断/填空应自动评分，简答应标记为待手动评分 | 高 | 准确性 |
| EXM-004 | 系统应记录每次考试的开始时间、结束时间、得分 | 高 | 审计追踪 |
| EXM-005 | 提交考试前必须完成电子签名确认 | 高 | 21 CFR 11 |
| EXM-006 | 管理员应可查看所有考生的成绩和签名 | 高 | 监管要求 |
| EXM-007 | 系统应支持上传考试试卷（PDF/Word/PPT），答题时可在页面展示 | 高 | 功能完整性 |
| EXM-008 | 系统应记录考生答题过程中的答案变更轨迹（答题留痕），包括变更前后答案、操作类型、答题用时、IP 地址 | 高 | 审计追踪 |
| EXM-009 | 管理员应可查看每份试卷的答题留痕时间线 | 中 | 监管要求 |

### 3.4 培训计划 (PLN)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| PLN-001 | 系统应支持创建培训计划，设定起止日期 | 高 | 计划管理 |
| PLN-002 | 计划应可关联多个课程和考试 | 高 | 综合培训 |
| PLN-003 | 系统应支持按用户/部门分配培训任务 | 高 | 任务分配 |
| PLN-004 | 系统应跟踪任务完成状态（未开始/进行中/已完成/已逾期） | 高 | 进度跟踪 |
| PLN-005 | 任务完成时应自动记录完成时间并计算用时 | 中 | 效率统计 |

### 3.5 日志与审计 (LOG)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| LOG-001 | 系统应记录所有用户的关键操作（登录、查看课程、下载、考试、签到） | 高 | 审计追踪 |
| LOG-002 | 日志记录应包含：用户、操作类型、时间戳、IP、设备信息 | 高 | ALCOA+ |
| LOG-003 | 日志记录应不可被用户删除或修改 | 高 | 数据完整性 |
| LOG-004 | 系统应支持按用户/时间/操作类型查询日志 | 中 | 审计效率 |
| LOG-005 | 管理员操作也应被记录到操作日志 | 高 | 审计追踪 |

### 3.6 电子签名 (SIG)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| SIG-001 | 系统应支持用户在手机上进行手写电子签名 | 高 | 21 CFR 11 |
| SIG-002 | 签名应与具体操作（考试提交/课程签到）绑定，不可分离 | 高 | 21 CFR 11 |
| SIG-003 | 签名记录应包含：签名图片、签名者、时间戳、IP、设备信息 | 高 | ALCOA+ |
| SIG-004 | 签名图片应以 PNG 格式加密存储，防止篡改 | 高 | 数据完整性 |
| SIG-005 | 签名后关联的记录应不可修改（系统锁定） | 高 | 21 CFR 11 |
| SIG-006 | 考试试卷和签到记录应展示签名及时间戳 | 高 | 可读性 |

### 3.7 安全与权限 (SEC)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| SEC-001 | 系统应实现基于角色的访问控制（RBAC） | 高 | 信息安全 |
| SEC-002 | 权限应细分到模块级别（查看/创建/编辑/删除/导出/审核/发布） | 高 | 最小权限 |
| SEC-003 | 系统应支持 HTTPS 加密传输 | 高 | 传输安全 |
| SEC-004 | 密码应以哈希形式存储（不可逆） | 高 | 信息安全 |
| SEC-005 | 系统应支持会话超时（24小时） | 中 | 会话安全 |
| SEC-006 | 生产环境应禁用 Debug 模式 | 高 | 信息安全 |

### 3.8 系统配置 (CFG)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| CFG-001 | 系统应支持可配置的成绩权重（视频+资料+考试=100%） | 中 | 灵活性 |
| CFG-002 | 系统应支持关键参数的可配置管理（通过 SystemConfig 模型） | 中 | 可维护性 |
| CFG-003 | 配置变更应记录到操作日志 | 高 | 审计追踪 |

### 3.9 基础设施 (INF)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| INF-001 | 系统应支持 PostgreSQL 数据库 | 高 | 数据可靠性 |
| INF-002 | 系统应支持 Redis 缓存（可选） | 低 | 性能 |
| INF-003 | 系统应支持 Nginx + Gunicorn 部署架构 | 高 | 生产环境 |
| INF-004 | 系统应提供每日自动备份机制（数据库+媒体文件） | 高 | 灾难恢复 |
| INF-005 | 备份数据应保留30天后自动清理 | 中 | 存储管理 |

### 3.10 题库管理 (QBN)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| QBN-001 | 系统应支持题目的增删改查，题目独立于考试存储 | 高 | 资源复用 |
| QBN-002 | 题目应包含：题目类型、难度（简单/中等/困难）、分值、知识点、标签 | 高 | 结构化管理 |
| QBN-003 | 系统应支持多维度筛选（类型/难度/知识点/标签/搜索） | 中 | 查询效率 |
| QBN-004 | 系统应支持通过 Excel 批量导入/导出题目 | 中 | 效率 |
| QBN-005 | 系统应支持知识点树形结构管理 | 低 | 知识体系 |
| QBN-006 | 系统应提供题库统计面板（题型分布、难度分布、热门标签） | 低 | 数据分析 |

### 3.11 自动出卷 (ATP)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| ATP-001 | 系统应支持创建出卷模板，定义题目类型、数量、分值、难度 | 高 | 出题效率 |
| ATP-002 | 出卷规则应支持限定知识点范围 | 中 | 精准出题 |
| ATP-003 | 系统应支持一键从题库中随机抽取题目自动组卷 | 高 | 公平性 |
| ATP-004 | 自动生成的考试应自动计算总分 | 高 | 数据一致性 |
| ATP-005 | 题目被引用到考试后，使用次数应自动 +1 | 低 | 使用统计 |

### 3.12 PPT 自动生成 (PPT)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| PPT-001 | 系统应支持根据课程信息和资料自动生成 PPT 课件 | 中 | 效率 |
| PPT-002 | 生成的 PPT 应包含：封面、课程概述、大纲、资料摘要、结束页 | 中 | 完整性 |
| PPT-003 | PPT 应支持彩色文件类型标识和资料描述 | 低 | 美观 |

### 3.13 大模型接入 (AI)

| 编号 | 需求描述 | 优先级 | 合规关联 |
|------|----------|--------|----------|
| AI-001 | 系统应支持接入多个大模型服务商（Kimi/豆包/阿里千问/OpenAI） | 高 | 灵活性 |
| AI-002 | 系统应支持配置 API Key、模型名称、温度参数、最大 Token | 高 | 安全性 |
| AI-003 | 系统应支持 AI 自动从学习材料生成题目并保存到题库 | 高 | 出题效率 |
| AI-004 | 系统应支持 AI 自动批改简答题（评分+评语） | 高 | 批改效率 |
| AI-005 | 系统应支持 AI 生成课程摘要 | 中 | 辅助学习 |
| AI-006 | 系统应记录每次 AI 调用的日志（Token 用量、耗时、成功/失败） | 高 | 审计追踪 |
| AI-007 | 系统应支持设置默认大模型，便于统一调用 | 中 | 易用性 |

## 4. 非功能需求

### 4.1 性能需求

| 编号 | 需求描述 | 目标值 |
|------|----------|--------|
| NFR-001 | 页面加载时间 | < 3 秒 |
| NFR-002 | 并发用户支持 | >= 100 |
| NFR-003 | 数据查询响应时间 | < 2 秒 |
| NFR-004 | 系统可用性 | >= 99.5% |

### 4.2 可用性需求

| 编号 | 需求描述 |
|------|----------|
| NFR-005 | 系统应支持响应式设计，适配手机、平板、PC |
| NFR-006 | 系统界面应为中文 |
| NFR-007 | 系统应提供清晰的操作反馈和错误提示 |

## 5. 数据完整性需求

| 编号 | 需求描述 |
|------|----------|
| DI-001 | 所有业务数据修改必须通过系统界面进行，禁止直接操作数据库 |
| DI-002 | 系统应自动记录所有数据的创建时间、修改时间 |
| DI-003 | 删除操作应为逻辑删除或记录详细删除日志 |
| DI-004 | 数据库应启用事务，确保数据一致性 |
| DI-005 | 上传文件应进行格式校验和大小限制 |

## 6. 合规需求

| 编号 | 需求描述 | 法规依据 |
|------|----------|----------|
| CMP-001 | 电子签名应绑定唯一用户身份 | 21 CFR Part 11 |
| CMP-002 | 审计追踪应不可删除、不可修改 | 21 CFR Part 11, EU GMP Annex 11 |
| CMP-003 | 系统时间应由 NTP 同步，不允许用户修改 | 21 CFR Part 11 |
| CMP-004 | 用户权限变更应记录审计日志 | EU GMP Annex 11 |
| CMP-005 | 系统应提供数据导出功能（如 Excel）用于监管检查 | 数据可用性 |
